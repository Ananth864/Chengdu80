Historical analysis and price-target summaries are independently selected analytic scopes, not an inseparable package and not dependencies of narrative research or news. Use the supplied current capability definitions for these scopes over conflicting older dashboard guidance. After exact Workflow approval and prepare_build, compose protected FinancialAnalysis through the supplied FinancialModules composition. Retrieve only through server adapters finance.historical-analysis and finance.price-target. Generated apps must not implement or modify financial algorithms in any scope.

## Shared Evidence Rules

Validate the selected SSE A-share exchange, six-digit string ticker, name and exact industry against the supplied canonical universe and approved company scope. Reject unknown or inconsistent identities rather than guessing. Tushare is the sole external financial provider; credentials, retrieval, caching, pagination, retries and provider access belong to the server. Apps cannot call providers directly or supply replacement observations or evidence.

Recorded live retrieval on 2026-10-15 Asia/Shanghai verified daily, adj_factor, income and report_rc for one representative ticker; see docs/tushare-verification.md. This is endpoint access and representative field evidence, not verification of every company, complete trading coverage, intraday freshness, brokerage rating mappings or target horizons. Keep transport success distinct from metric availability. Preserve provider, source, as_of_date, retrieved_at, actual coverage, per-field status, basis and limitations. Fixture observations must remain visibly synthetic, never a fallback for a live request. Missing credentials, denied permissions, partial retrieval, empty results and errors must remain distinguishable.

## Historical Prices

finance.historical-analysis implements the supplied historical-analysis scope. Chart choices are 1 month, 6 months, 1 year and 5 years; retrieve at most five years. Display current/latest observed raw close, 52-week raw high and low, available-period raw high and low, adjusted maximum drawdown, amount/percentage distances from the 52-week extremes, and daily amount/percentage change where supported. Label latest close as end-of-day, not a live intraday quote. Show actual dates; do not claim complete listing history, all-time extremes or five-year coverage when fewer observations are available.

The server defines the inclusive 52-week window as latest quote date D minus 363 calendar days through D, using raw daily highs/lows rather than closes. Available-period extremes use the full retrieved history; charts and drawdown use the selected period. Short/incomplete coverage is partial. Distance amount is latest raw close minus reference; percentage is (latest raw close / reference - 1) * 100. Daily change uses the preceding trading close on the documented raw basis; disclose any provider pre_close fallback, corporate-action mismatch or unverified gap rather than inventing a session.

Maximum drawdown requires at least two selected-period adjusted closes joined to valid positive ticker/date factors. The documented Tushare multiplicative convention is adjusted_close_t = raw_close_t * factor_t / factor_reference, using one common observed reference date. The server returns min(adjusted_close / running_peak - 1) as a non-positive fraction; display it as a percentage. Missing or invalid required factors make drawdown unavailable, not a raw-price calculation. Supported raw metrics remain visible independently. Preserve the returned formula, reference date, adjustment basis and actual calculation period. These are protected server definitions, not instructions to reproduce calculations in generated code.

Optional annual revenue/profit visualizations require separately sourced, consistently defined statement periods, currency, publication dates and reporting scope. Price history and the undated market-cap CSV do not establish financial performance or authorize the six investment-metric algorithms.

## Brokerage Summaries

finance.price-target implements sourced Tushare report_rc brokerage summaries, never local forecasting or app-generated investment opinions. Use the inclusive 90-calendar-day report window ending on as_of_date, starting as_of_date minus 89 days. Deduplicate forecast-quarter rows into reports, select the latest distinct report per evidence-backed brokerage, and count at most one contribution per brokerage. No silent backfill from older reports. Exclude unresolved identities and conflicting unorderable same-date opinions from the affected summary; provider create_time does not establish publication order.

Normalized ratings require versioned brokerage-specific mappings with server-owned source evidence. Retain originals, mapping versions and exclusions. Display Strong Sell, Sell, Hold, Buy and Strong Buy counts, including zeros, with the mapped brokerage count. The summary is Most common brokerage rating: unique mode, Mixed for a positive tie, unavailable for zero mapped opinions. A majority requires more than half. Do not translate wording into an assumed common scale, average category scores, treat missing ratings as Hold or infer ratings from target upside.

Targets require both finite positive CNY bounds with minimum <= maximum, compatible per-share basis, and server-owned verified horizon/reference evidence. A financial forecast quarter and report freshness window are not target horizons. Group only matching verified horizons and compatible conventions; keep report-date durations separate from fixed target dates. A duration is not an exact future chart date.

The protected server computes one midpoint (minimum + maximum) / 2 per eligible brokerage and an equally weighted mean only with at least three eligible brokerages in that horizon group. Label it Average brokerage target midpoint, not official consensus. Below three, aggregate midpoint and implied difference are null with insufficient_brokerage_coverage; independently validated individual targets may remain visible. Implied difference is (average midpoint / latest valid raw close - 1) * 100 only on compatible bases; show quote date, CNY, actual horizon, count and source dates. Label negative values downside, not guaranteed returns.

Mapped ratings and target groups may remain unavailable despite successful report_rc retrieval. Brokerage aliases, rating mappings, horizon evidence and quote basis are server-owned configuration, never generated-app/request inputs. Do not fabricate evidence to populate panels. Missing mappings must not suppress independently supported targets, and missing horizons/targets must not suppress valid ratings. Attribute Buy/Sell labels to brokerage opinions, not personalized recommendations. Preserve independent statuses, provenance and explicit reasons for unverified_target_horizon and all other exclusions.
