# Independent Risk, Preferences and Company Discovery

## Current Discovery Contract

New prepared React discovery builds use protected CompanyDiscovery from @/components/company-discovery through finance.company-discovery.v1-3, the neutral company-discovery v1.3 contract. Discovery is an explicitly enabled add-on to industry preferences, not a mandatory feature or a new standalone reusable capability. Risk assessment and preference capture work independently; neither requires discovery. Only enabled discovery requires both a completed validated risk_result and consistent normalized industry_preference. Missing inputs remain missing, never a default profile or implicit all-supported preference. Executable scope and permissions come from the exact approved prepared record, not this document.

Risk maps only to supplied CSV size: low to Large cap, medium to Mid cap, high to Small cap. Independently filter by normalized preferences for the five exact CSV industries. Use assigned size categories, not new capitalization thresholds or industry risk rankings. Validate SSE identities, string tickers, supported labels and sizes; deduplicate by exchange+ticker and report invalid/conflicting catalog records. Never widen either filter to fill a session.

Optional excluded_company_ids contains canonical exchange+ticker identities excluded by app-owned state; absent means no app exclusions. Shuffle once per new session, select at most five distinct identities and display one company per round. Use fewer rounds for a smaller eligible pool; never repeat within a session or reshuffle on advancement. Session state is memory-only; refresh abandons it. Prior exposure alone does not permanently exclude a company, and a new session can include prior companies unless app exclusions prevent it. Return explicit ready, exhausted, invalid_input and session_completed states with catalog validation and limitations. Waiting alone does not update the supplied dataset.

The app defines card actions and any optional saved-company list according to the approved user requirements. The neutral capability returns identities and advances session state; it does not implement a watchlist, require Add/Skip actions, mandate storage keys or persist decisions. Do not impose a watchlist feature. If an optional app-owned list is requested, use permission-checked platform storage, validate unique SSE:ticker identities and acknowledge saves only after storage succeeds. The app may derive optional exclusions from its own choices. No browser localStorage is available. Financial metrics are a separate dashboard concern; their failure must not block neutral session advancement. Discovery supplies no live quotes, financial ranking, returns prediction, suitability assessment or brokerage action.

## Independent Industry Preferences

Compose protected IndustryPreference from @/components/industry-preference for approved prepared preference scope. Capture is independent: no risk result, questionnaire, company catalog or market data is required. The platform derives executable permissions from the approved prepared scope; markdown does not grant finance.industry-preferences or storage access. Contract v1.3.0 capture_preferences accepts selected_industries using only the five canonical IDs manufacturing, information_software_it, utilities, financial_services and wholesale_retail. Deduplicate selections in first-occurrence order. An explicitly submitted empty array produces selection_mode=all_supported with all five effective IDs; an absent or invalid array is invalid, not an implicit all-supported choice. Explicitly selecting all five remains selection_mode=selected. Persist only the validated completed normalized industry_preference under industry-preference through platform storage after successful capture; report a save only after storage succeeds. Do not persist drafts or infer preferences from questionnaire answers. filter_companies matches industry_labels against company industry values using exact labels from the protected five-industry CSV taxonomy, preserving input record order and duplicates; an explicit empty label array preserves all records. Do not translate, fuzzy-match or widen selected labels. All-supported discovery permits these industries subject to the independent size filter, not equal industry representation. Basic filtering needs no risk result or session state and does not authorize financial metrics.

## Independent Risk Profile

The protected RiskQuestionnaire from @/components/risk-questionnaire implements the seven-question v0-demo provisional profile via finance.risk-profile. Compose it only when requested, Workflow-approved and prepared. It has no discovery or industry-preference dependency. Preserve exact question wording and three choices; do not recreate scoring, invent a result or change it based on card actions.

Validation requires exactly q1 through q7 integer answers 1-3 and questionnaire_version=v0-demo; reject incomplete, extra, unsupported-version or invalid inputs without a score or bucket. The protected scorer sums all seven equally: 7-11 low, 12-16 medium, 17-21 high. Keep total_score and risk_profile_bucket hidden, discard partial answers on exit/refresh and persist only validated completed results under risk-profile through platform storage. The provisional profile combines willingness, capacity indicators and expectations; it is not an official suitability assessment, user-facing recommendation or forecast. Questionnaire completion alone does not authorize discovery, select companies or assign industries.

## Analysis and Skills

P/E, P/S, dividend yield, revenue growth, ROE and interest coverage belong to dashboard skills and protected metric modules, not reusable capability IDs or discovery algorithms. Explicit cardMetrics selections replace defaults; preserve unavailable selected metrics with reasons. Do not introduce formulas, peer medians or metric modifications in generated code in any scope. Education, charts, storage and grounded chat are also skill-guided composition, not new financial capabilities.

Optional historical analysis, historical listed-company industry research and sourced brokerage summaries use protected FinancialAnalysis with finance.historical-analysis, finance.industry-research and finance.price-target for their own approved scopes. They are server-backed, not globally pending, and are not prerequisites for discovery or decisions. Do not add news automatically or invent a new news contract. Follow history.md and research.md, including independent availability, as_of_date, partial industry coverage and server-owned rating/horizon evidence. Never fabricate observations, all-time metrics, industry forecasts or national market size.
